# Ask the Model v0.2.0

**Local Chat Baseline — 2026-09-19**

Ask the Model v0.2.0 is the first release in which the application performs functional local AI conversation.

The release advances AtM from the v0.1.x shell/documentation baseline to a usable local-chat baseline while preserving the core scientific boundary: AtM is an interface, not a replacement for EWD, CBD, RMD or any other scientific-model repository.

## User-visible functionality

- local Ollama-compatible provider discovery;
- preferred standalone local-provider endpoint at `127.0.0.1:11434`;
- compatibility fallback at `127.0.0.1:11435`;
- automatic inspection of installed model capabilities;
- exclusion of embedding-only models from the chat selector;
- header-bar AI-model selector;
- manual circular Refresh control;
- real percentage progress while installed models are checked;
- temporary model-scan result after refresh/startup;
- streamed assistant responses;
- in-memory multi-turn chat during the current application session;
- automatic system light/dark following;
- X11 Cairo renderer fallback for the GTK/GSK compatibility path.

## Provider architecture

AtM does not bundle or control the inference provider.

The preferred architecture for this release is:

```text
Local Ollama-compatible service
        ├── AtM
        └── optional other local frontends
```

AtM tries `11434` first and retains `11435` only as a compatibility fallback.

## Provider/API compatibility

The release depends on Ollama-compatible behavior for:

- `GET /api/tags`;
- `POST /api/show`;
- `POST /api/chat`.

Chat requests use `stream: true` and `think: false`.

Only models exposing `completion` are considered usable chat models.

Compatibility is API-based rather than tied to a particular locally tested provider version.

## Runtime baseline

The packaged baseline is elementary OS 8 with the elementary Platform/SDK 8 Flatpak runtime and a standalone local Ollama-compatible service.

Hardware acceleration is handled by the external provider and is not part of AtM's application-level hardware contract.

## Flatpak/runtime dependencies

The Flatpak uses:

- GTK 4;
- Granite 7;
- libsoup 3;
- json-glib 1;
- `--share=network` for host-local provider access;
- Wayland and fallback-X11 sockets;
- DRI device access.

## Conversation behavior

Conversation history is kept in memory only.

Changing the selected AI model changes the active inference model; v0.2.0 does not yet create or persist separate conversations automatically.

No conversation history survives an application restart.

## Scientific boundary

v0.2.0 does **not** yet ingest or retrieve content from EWD, CBD, RMD or other scientific repositories.

Therefore the release does not yet provide repository-grounded answers, provenance tracing or canonical scientific-model results.

Scientific repositories remain external and authoritative.

## Known limitations / not implemented

- repository ingestion and retrieval;
- scientific-repository context selection;
- citations/provenance;
- conversation persistence;
- application/provider settings;
- provider endpoint configuration;
- model installation/download/deletion;
- cloud AI providers;
- model tool use;
- scientific-model execution/simulation;
- autonomous repository modification.
