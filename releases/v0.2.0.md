# Ask the Model v0.2.0

**Local Chat Baseline — 2026-09-19**

Ask the Model v0.2.0 is the first release in which the application provides functional local AI conversation.

The release advances AtM from the v0.1.x application-shell baseline to a usable local-chat baseline while preserving the project's central boundary: AtM is an interface, not a replacement for EWD, CBD, RMD or any other scientific-model repository.

## Included

- local Ollama-compatible provider discovery;
- preferred standalone local-provider endpoint at `127.0.0.1:11434`;
- compatibility fallback at `127.0.0.1:11435`;
- installed-model enumeration and capability inspection;
- exclusion of embedding-only models from the chat selector;
- header-bar AI-model selector;
- manual circular Refresh control;
- real percentage progress while installed models are checked;
- temporary model-scan result after refresh and startup;
- streamed assistant responses;
- in-memory multi-turn chat during the current application session;
- automatic system light/dark following;
- X11 Cairo renderer fallback for the GTK/GSK compatibility path;
- elementary OS 8 Flatpak packaging and continuous build verification.

## Application status

The application can discover a compatible local provider, identify completion-capable models, select the active AI model and maintain a streamed multi-turn conversation for the current session.

AtM does not bundle or control the inference provider. Compatibility is based on the Ollama-compatible API operations used by the application:

- `GET /api/tags`;
- `POST /api/show`;
- `POST /api/chat`.

Chat requests use `stream: true` and `think: false`.

Conversation history is kept in memory only and does not survive an application restart.

## Compatibility and dependencies

The packaged baseline is elementary OS 8 with the elementary Platform/SDK 8 Flatpak runtime.

The Flatpak uses GTK 4, Granite 7, libsoup 3 and json-glib 1. Network sharing is required for host-local provider access; Wayland and fallback-X11 sockets and DRI device access are included in the manifest.

Hardware acceleration is handled by the external provider and is not part of AtM's application-level hardware contract.

See `docs/DEPENDENCIES_AND_COMPATIBILITY.md` for the complete compatibility contract.

## Scope boundary

v0.2.0 does not implement:

- scientific-repository ingestion or retrieval;
- EWD/CBD/RMD context selection;
- source citation or provenance tracing;
- conversation persistence;
- application/provider settings;
- provider endpoint configuration;
- AI-model installation, download or deletion;
- cloud AI providers;
- model tool use;
- scientific-model execution or simulation;
- autonomous repository modification.

Scientific repositories remain external and authoritative. Ordinary local-chat responses in this release are not repository-grounded scientific results.

## Versioning

AtM remains in initial development. The move from 0.1.1 to 0.2.0 reflects substantial new backward-compatible functionality rather than a patch-only correction.
