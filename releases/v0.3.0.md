# Ask the Model v0.3.0

**Repository-Grounded Multi-Chat — 2026-09-21**

Ask the Model v0.3.0 is the first public repository-aware release. It extends the v0.2 local-chat baseline with validated scientific-repository snapshots, deterministic local retrieval, per-chat repository/model pinning and inspectable immutable provenance for grounded answers.

## Included

- fixed EWD/CBD/RMD repository catalog in the GTK application;
- explicit repository Refresh and Download/Update lifecycle controls;
- exact remote Git SHA resolution before download;
- bounded safe archive extraction and strict manifest validation;
- immutable validated repository snapshots under `~/Ask the Model/Repositories`;
- regenerable per-snapshot SQLite/FTS5 retrieval indexes;
- exact technical-ID, structured entity/relation, lexical BM25 and tabular row-key retrieval;
- conservative Romanian/English query normalization;
- deterministic source authority, deduplication and cross-repository scoping;
- independent multi-chat tabs with per-tab provider history and retrieval state;
- first-Send freeze of AI-model identity and repository snapshot scope;
- repository-grounded generation with current-turn-only evidence;
- compact numbered source references;
- source-detail windows with repository/version, exact snapshot SHA, source path/locator, logical source ID, readable excerpt and immutable GitHub permalink;
- readable plain-text presentation for Markdown evidence;
- ordinary zero-repository local chat retained as a separate streaming path;
- documented interface map and extension-oriented developer guide.

## Repository lifecycle and safety

Repository updates are explicit. AtM resolves the tracked branch to an exact SHA, downloads that revision into staging, validates it, builds and validates its retrieval index, and only then promotes the snapshot.

A failed refresh or update does not turn stale/partial data into READY and does not destroy the last valid snapshot.

The Flatpak requests write access only to the dedicated `~/Ask the Model` directory rather than broad Home or host filesystem access.

## Grounding and provenance

AtM does not send entire repositories to the language model.

For each grounded turn it retrieves a bounded evidence set from the repository snapshots pinned to that conversation. Repository text is treated as untrusted data, not as behavioral instructions.

Temporary source labels are resolved by AtM into persistent provenance objects. User-visible source details can expose the exact immutable repository revision supporting an answer.

## Multi-chat identity

Each chat tab owns its own:

- selected AI model identity;
- selected repository set and exact snapshot SHAs;
- provider conversation history;
- deterministic retrieval conversation state;
- citation objects.

After the first Send, the model and repository selectors remain visible but are locked for that chat. A different model or repository scope requires a new chat.

## Verification

The release candidate is covered by the Meson/Flatpak test suite and deterministic repository/retrieval gates.

Local smoke testing on elementary OS 8 / GTK 4.14 verified:

- EWD/CBD/RMD Refresh behavior;
- update of only the repository whose SHA changed;
- preservation of previous immutable snapshots/indexes;
- grounded EWD+CBD+RMD conversation;
- per-chat selector freeze;
- source-reference detail windows;
- exact commit-pinned GitHub permalinks;
- readable Markdown source excerpts.

The reviewed frozen R5 benchmark remains deterministic and separate from scientific validity claims.

## Boundaries retained

v0.3.0 does **not**:

- install, start, stop or update the external AI provider;
- download/import/delete AI model files through AtM;
- persist conversations across application restarts;
- accept arbitrary unreviewed repository origins;
- execute or simulate EWD, CBD or RMD;
- autonomously modify scientific repositories;
- convert generated text into an authoritative scientific-model result.

EWD, CBD and RMD remain authoritative for their own model definitions, data, assumptions, provenance and validation.
