# Ask the Model v0.2.1

**Installation and release-distribution correction — 2026-09-19**

Ask the Model v0.2.1 is a patch release that preserves the v0.2.0 Local Chat Baseline while correcting how the application is presented, downloaded and installed.

## Included

- automatic attachment of `AskTheModel.flatpak` to the versioned GitHub Release;
- a stable `releases/latest/download/AskTheModel.flatpak` direct-download path;
- a clearer README installation path for normal users;
- explicit installation order: Flatpak, local provider, completion-capable model, then AtM;
- explicit separation between normal-user dependencies and developer-only build dependencies;
- elementary OS / Ubuntu package guidance for native source builds;
- Node 24-compatible `actions/github-script@v9`;
- release-asset integrity protection: a missing asset is uploaded to an existing release only when its tag points to the exact workflow commit.

## Application status

The local-chat functionality is unchanged from v0.2.0.

AtM can discover a compatible local provider, identify completion-capable models, select the active AI model and maintain a streamed multi-turn conversation for the current session.

## Distribution

The GitHub Release now includes the single-file Flatpak bundle:

`AskTheModel.flatpak`

The stable latest-release download path is:

`https://github.com/LaurentiuStaicu/ask-the-model/releases/latest/download/AskTheModel.flatpak`

The separate `AtM Development` Flatpak repository remains a development update source and is not promoted as the primary public installation channel.

## Compatibility and dependencies

The application compatibility contract remains the same as v0.2.0:

- preferred local-provider endpoint `127.0.0.1:11434`;
- compatibility fallback `127.0.0.1:11435`;
- required `GET /api/tags`, `POST /api/show` and `POST /api/chat` behavior;
- completion-capable models only in the selector;
- elementary OS 8 Flatpak baseline;
- provider-owned CPU/GPU inference.

Normal release users do not need Meson, Vala, GTK/Granite development packages or the elementary SDK. Those are development dependencies only.

See `docs/DEPENDENCIES_AND_COMPATIBILITY.md` for the complete compatibility contract.

## Scope boundary

v0.2.1 does not add:

- scientific-repository ingestion or retrieval;
- EWD/CBD/RMD context selection;
- source citation or provenance tracing;
- conversation persistence;
- provider settings;
- AI-model installation or deletion;
- cloud providers;
- scientific-model execution or simulation.

Scientific repositories remain external and authoritative.

## Versioning

This is a patch release because it corrects distribution and installation behavior/documentation without adding new application functionality.
