# Ask the Model v0.7.0

Released: 2026-10-14

**Two explicitly qualified scientific chart profiles, with source provenance preserved through History — 2026-10-14**

## Summary

v0.7.0 adds the source-qualified Energy Institute Total Energy Supply (TES) chart path alongside the established GISTEMP v1 route. It also strengthens startup reconciliation for managed conversation exports and hardens the generic native SeriesContract boundary.

## Changes

- Add the source-qualified Energy Institute TES chart flow via `/chart energy-institute`, alongside the existing qualified GISTEMP path.
- Reconstruct saved chart recipes and chart/Data presentation from the exact pinned processed EWD source and source profile. Numeric points and rendered pixels are not persisted as independent scientific truth.
- Reconcile managed conversation JSON exports before startup cleanup. When reconciliation fails or remains uncertain, retain the unarchived working SQLite row so recoverable state is not silently discarded; successful later reconciliation can resume normal cleanup.
- Require canonical UTC-instant SeriesContract scopes to enclose the ordered points and bind numeric/source-token metadata to authorized finalized SRA facts. Contradictory numeric payloads on matched `MISSING` facts are rejected.

## Scope and qualification boundaries

- Chart admission remains limited to the explicitly qualified GISTEMP v1 and Energy Institute TES v2 profiles on reviewed, pinned EWD snapshots; unknown/mixed snapshots and changed source bytes fail closed.
- Energy Institute chart values reflect the admitted processed EWD snapshot. This release does not claim independent reproduction of the Energy Institute upstream raw-to-processed pipeline.
- BNR C01 remains native/test-only and has no application chart route. M4 reduction remains dormant.
- Arbitrary sources, model-authored numeric chart data, generic multi-series/derived charts and generalized missing/event/discontinuity chart semantics are not introduced. Broader CHART-01 qualification remains open in issue #343.
- Optimizations remain session-only and default OFF.

## Verification boundaries

The release workflow validates the synchronized release metadata, builds the Flatpak and runs the bundled test suite before publication. Automated GTK Application E2E coverage exercises both qualified chart paths, Save to History, separate-process History reconstruction and fail-closed handling after source-manifest tampering. These checks do not constitute a claim of independent scientific certification or manual visual review on every supported desktop installation.
